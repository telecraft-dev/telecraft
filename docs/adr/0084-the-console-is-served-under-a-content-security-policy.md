# ADR-0084: The console is served under a Content Security Policy read off the document it is sent with

- Status: accepted
- Date: 2026-08-30

## Context

The Instance server sends the console document with a `Content-Type` and a
`Cache-Control` and nothing else. No Content Security Policy, no
`X-Content-Type-Options`, no `Referrer-Policy`, no
`Strict-Transport-Security`. Nothing in the repository has ever named one.

That was survivable while every reader was somebody who had built the
binary. ADR-0072 puts the console on the public internet for customers who
are not us, and ADR-0069 puts many Organisations behind one front door, so
the population that would be hurt by an injected script is now other
people's estates.

What makes a policy cheap here is a decision already taken. ADR-0045 §5
forbids runtime CDN dependencies and `console/tools/check-zero-cdn.mjs`
fails the build on an external reference, so every font, icon, stylesheet
and chunk the console loads is vendored and served from this origin.
`default-src 'self'` therefore describes what the bundle already is. It
constrains nothing, and it costs nothing to hold, because the check that
keeps it true runs on every pull request.

There is one thing in the bundle that is not a file. `console/index.html`
carries an inline script that resolves the theme before the first paint:
`tokens.css` carries dark on the bare `:root`, so a reader who chose light
would otherwise see one dark frame before the shell mounts. Moving it into
a file is what would break it, because a file is fetched and a frame has
already been painted by the time it arrives.

`'unsafe-inline'` would admit it, and would admit every other inline script
with it, which is the thing a policy exists to stop. A hash admits that
script and no other. The cost of a hash is that it must match the bytes
served, exactly, and a build that changed the resolver by one space would
otherwise ship a policy that blocks the console it is served with.

## Decision

### 1. The console document is served under a policy, and the policy is read off the document

The policy is computed from the bundle this binary carries, at the time the
console handler is built, by hashing the body of every script element in
`index.html` that has no `src`. It is not written down as a constant and it
is not generated by the build into a file somebody has to keep in step.

This is the whole of what makes the hash safe to rely on. A policy derived
from the document cannot disagree with the document. The resolver can be
edited, vite can inline something new, and the header follows without
anybody remembering that it should.

The policy is seven directives:

```
default-src 'self'; script-src 'self' 'sha256-...'; style-src 'self'
'unsafe-inline'; object-src 'none'; base-uri 'none'; form-action 'self';
frame-ancestors 'none'
```

`script-src` repeats `'self'` because it carries the hashes.
`object-src`, `base-uri`, `form-action` and `frame-ancestors` are each
outside what `default-src` covers, or worth saying twice. Nothing else is
listed, because a directive that only restates the default is one more
thing to keep true.

`frame-ancestors 'none'` is there because nothing should frame a tenant's
console, and because the hosted service puts each Organisation on a host
beside its siblings (ADR-0072 §2).

### 2. Inline styles are admitted, and inline scripts are not

`style-src` carries `'unsafe-inline'`. The bundle sets element styles from
JavaScript throughout, the canvas ADR-0045 §2 chose does it on every node
on every frame, and the dialog primitives ADR-0045 §4 chose inject a
stylesheet while a dialog is open. A policy that forbade both would break
the console rather than harden it, and it would break it in the surfaces
that are hardest to notice.

The loosening is named here rather than left to be discovered, because it
is the one place the policy is weaker than it reads. Scripts are where the
defence is: an injected `style` attribute is a defacement, an injected
script is the estate.

### 3. Three other headers go on every answer, not on the document alone

`X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` are
sent with every answer from the address humans reach: documents, assets,
API answers and the two probes. They are one wrapper around the whole mux
rather than a line in each handler, so a route added later cannot be added
without them.

`no-referrer` rather than a narrower policy because nothing this console
links to needs a referrer, and a console URL names the estate it governs.

### 4. Strict-Transport-Security follows the external URL, and carries no `includeSubDomains`

The process holds no certificate in any deployment shape and TLS terminates
in front (ADR-0067 §5), so the only thing that knows whether a browser
reaches this instance over TLS is the external URL. A deployment whose
external URL is https sends `Strict-Transport-Security`. A loopback
Instance (ADR-0082) and a deployment given `-insecure-http` send none: a
plain HTTP deployment that told a browser to refuse plain HTTP would have
locked itself out of itself.

The header is one year and stops there. `includeSubDomains` would commit
every other host under the operator's domain to HTTPS, and this process
knows the URL it is reached at and nothing whatever about what else the
operator runs beside it. That is not its promise to make.

### 5. The fixture backend sends the same headers

`console/tools/fixture-backend.mjs` already mirrors the auth handler,
because the Playwright suite runs the built console against it. It mirrors
these headers for the same reason: a policy the suite does not run under is
a policy nothing proves the console still works under.

## Consequences

- A change to the theme resolver changes the hash, and nothing has to be
  remembered for that to happen. A change that adds a second inline script
  is admitted the same way.
- A future dependency that needs `eval` or a remote origin does not fail
  quietly. It fails in the browser, in the Playwright suite, on the surface
  that needs it. That is the point, and it is the correct time to have the
  argument about whether to take the dependency.
- The zero-CDN check and the policy now hold each other up. The check keeps
  `default-src 'self'` true over the build; the policy keeps it true at run
  time in a browser, which is where it was only ever a convention before.
- The demo site is published to a static host from
  `console/tools/assemble-site.mjs` and sends no headers, because a static
  host is where its own configuration lives rather than in this repository.
  It serves fixture data and governs nothing, and its policy is a separate
  question from this one.
- `-external-url` now decides a third thing, after ADR-0067 §5's `Secure`
  flag and ADR-0083's cookie name: whether a browser is told to refuse
  plain HTTP. All three follow the same scheme, so an operator moving to
  HTTPS gets all three at once.
- Nothing an operator configures changes the policy. There is no flag to
  loosen it, because a deployment that needed a looser one would be a
  deployment running something the zero-CDN rule forbids.
- No requirement row changes. REQ-006 is what the zero-CDN rule serves and
  this enforces it at the browser rather than adding to it.
- No glossary term is introduced. A response header is a web convention,
  not a domain term.
